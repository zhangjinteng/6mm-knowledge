# 知识库独立服务设计

## 范围

从 workflow-zjt 提取知识库 HTTP 模块、实际依赖的服务代码及原 Next 应用中的训练消费者。原仓库保持只读，不复制工作流/聊天 HTTP 路由、不复制业务数据库。保留上游许可与来源。

API、训练任务、MongoDB 单节点副本集、PostgreSQL/pgvector、Redis、S3 兼容存储在一个容器中运行。模型推理调用已有外部 API。数据库只监听容器内部；持久化目录独立于镜像。先部署指定测试服务器，不操作已有生产网站。

## 兼容性与安全

保留 /api/core/dataset 下 60 个 HTTP 路径、JSON 包装及文件下载语义。保留团队、成员、API key、会话和知识库权限验证；以独立数据库初始化服务身份，不复用原系统数据库、会话或管理员密码。外部数据源继续使用原来的凭据字段和来源适配器。默认禁止匿名访问，限制请求大小和解析并发，日志隐藏凭据。

## 任务处理

HTTP 写入持久化训练记录；独立消费者负责 parse、QA、embedding。启动时处理存量任务，定期扫描弥补 change stream 中断。健康检查必须验证依赖和消费者心跳，不以 HTTP 进程存活代替就绪。关闭时先停止接单与消费者，最后关闭数据库。

## 验收边界

逐接口记录已实现、模拟测试、真实成功、缺资源未验收，不用 401/404/空结果充当成功。核心验收覆盖创建、入库、任务完成、搜索命中、更新、删除与重启恢复。用户确认暂时没有飞书/钉钉/语雀账号，因此这些保留实现并进行模拟测试，真实账号接入明确未验收。增强 PDF/OCR 同样需要真实模型/解析提供商配置。

## 部署限制

测试服务器通过用户已登录 1Panel 浏览器会话操作。不直接 SSH，不修改已有应用和数据库。服务启动前检查端口及目录，使用独立容器名称和持久化目录。原始低配目标仅 1 核 / 1.8GB，当前不部署。具体服务器地址不提交到公开仓库。
